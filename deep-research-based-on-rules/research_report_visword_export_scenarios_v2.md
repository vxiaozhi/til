# Visword v2：跨平台导出格式规范 + 扩充场景研究

## 执行摘要

本报告在上次动态场景研究的基础上完成两个关键转向：(1) 从"一键发布 API 集成"转为更务实的"一键导出为各社交平台最优格式"——用户自行上传，Visword 保证导出的文件在目标平台上获得最佳画质；(2) 在原有 5 个场景基础上扩充至 15 个动态视频场景，并按市场热度、技术难度、竞品空白度三维评分重新排定优先级。

核心发现：**单一通用导出格式**——MP4 容器、H.264 编码、1080x1920 竖屏、30fps、10-12Mbps VBR 码率、AAC-LC 48kHz 音频——可以覆盖全部 10 个主流社交平台。按"平台预设"导出的价值在于自动匹配各平台的码率上限和宽高比差异（如微信视频号的 6:7 特殊比例），避免用户手动选择导致的上传失败或画质损失。

扩充后场景优先级重新排序为：**①动态增长曲线/图表动画 ②Top-N 排名揭晓动画 ③VS 对比动画 ④知识卡片/金句动画 ⑤地图轨迹动画 ⑥AI 新闻简报动画 ⑦模拟聊天对话 ⑧时间线/历史动画**，其余 7 个场景作为后续扩展。

## 第一部分：跨平台导出格式完整规范

### 1.1 通用安全格式（一次导出，全平台可用）

```
容器:     MP4
视频编码:  H.264 (AVC), High Profile
分辨率:   1080 x 1920 (9:16 竖屏)
帧率:     30 fps (整数帧率)
码率:     10-12 Mbps VBR (2-pass)
色彩:     SDR, Rec.709, yuv420, 8-bit
关键帧:   每 2 秒一个 GOP
音频编码:  AAC-LC
音频采样:  48 kHz
音频码率:  192-256 kbps, Stereo
```

此格式在全部 10 个主流平台上可正常上传且不会被二次压缩到影响画质的程度。

### 1.2 各平台差异化导出预设

| 平台 | 特殊要求 | 推荐导出微调 |
|---|---|---|
| **TikTok** | Android 仅 72MB，iOS 287MB | 码率降至 8Mbps（60秒内）或分两段导出 |
| **抖音** | 超 12Mbps 触发重压缩 | 码率上限 12Mbps，网页上传绕过 App 限制 |
| **Instagram Reels** | 禁用 H.265（会导致上传失败） | 严格 H.264，禁用 60fps（触更重压缩） |
| **YouTube Shorts** | ≤60 秒才入 Shorts 推荐 | 保持 10-12Mbps，唯一可从 4K 受益的平台 |
| **微信视频号** | **推荐 6:7 (1080x1260)** 非标准比例 | 单独导出 6:7 比例版本，无二维码/Logo |
| **小红书** | 支持 3:4 和 9:16 | 美妆穿搭类优先导出 3:4 (1080x1440) |
| **B站** | 禁小数帧率 (29.97/59.94) | 严格整数帧率，≤6000kbps 码率更稳 |
| **快手** | 禁用 H.265，禁非标准宽高比 | 严格 9:16，≤8000kbps 码率 |
| **Snapchat** | 5-60 秒，无水印 | 最短时长要求 |
| **Facebook Reels** | 最宽松（全格式接受） | 按通用格式即可 |

### 1.3 关键导出禁忌（Top 10 常见错误）

1. **用 H.265/HEVC 导出** — Instagram/Kuaishou 上传失败或画质劣化
2. **4K 导出反而画质更差** — TikTok/Douyin/Instagram 对 4K 重压缩更狠
3. **忽略手机端文件大小上限** — TikTok Android 72MB 最严限制
4. **小数帧率 (29.97)** — Bilibili 直接拒绝
5. **非标准宽高比 (18:9)** — 快手拒绝
6. **多音轨/字母轨** — Bilibili 拒绝
7. **10-bit 色彩** — Bilibili 触发重压缩
8. **超码率** — 抖音>12Mbps 触重压缩、快手>8Mbps、B站>6Mbps
9. **重新上传已压缩过的视频** — 多代压缩灾难
10. **忘记平台级"高清上传"开关** — TikTok/Douyin 每次发帖需重新打开

### 1.4 Visword 导出功能设计建议

在导出界面提供 3 个选项：
- **「通用格式」** — 上述安全格式，一键导出 MP4，适配所有平台
- **「平台预设」** — 下拉选择目标平台，自动匹配最优参数（TikTok/Douyin/Reels/Shorts/视频号/小红书/B站/快手）
- **「自定义」** — 高级用户手动调整分辨率/帧率/码率

用户导出的是一个可以直接拖入对应 App 上传的 MP4 文件，不需要 Visword 做任何 API 集成。

### 重点场景详解

#### 🥇 场景 1：动态增长曲线/图表动画（长期首选）

**用户场景**: "我想做一个 30 秒的视频展示过去 10 年全球 AI 公司市值的排名变化"
**AI 做什么**: 自动获取数据（维基百科/公开数据集/用户 CSV）→ 选择最佳图表类型（bar race/line growth/pie explode）→ 生成动画 + 标题 + 要点标注
**用户编辑什么**: 配色方案、关键数据点的标注文字、背景音乐节奏匹配、片头片尾文字、特定品牌 Logo 替换
**导出格式**: 1080x1920 竖屏，30fps，10Mbps，MP4，15-60 秒
**技术路线**: RacingBars（bar chart race）+ ECharts（line/pie）+ Remotion（导出视频）+ LLM（数据收集+标题生成）
**竞品**: Flourish（Web 端标准但无移动端/无 AI 数据发现/无编辑后一键导出）、ChartGlow（TikTok 优化但桌面 Web 工具）
**为什么排第一**: Flourish 的 bar chart race 模板是公认的 viral 格式（单个视频 878 万 YouTube 播放），但现有工具全是桌面 Web 端，移动端"AI 发现数据→生成动画→编辑→导出"完全空白

#### 🥈 场景 2：Top-N 排名揭晓动画

**用户场景**: "2026 年十大最值得学的编程语言，从第 10 名到第 1 名逐个揭晓"
**AI 做什么**: 根据话题生成排名列表 + 每个排名项的理由文字 + 自动匹配图标/emoji + 设计揭晓动画节奏
**用户编辑什么**: 排名顺序、每个项的描述文字、揭晓间隔时长、音效选择、配色
**导出格式**: 1080x1920 竖屏，30fps，8-12Mbps，30-90 秒
**技术路线**: GSAP Timeline（序号揭晓动画）+ Lottie/图标库 + Remotion 导出
**竞品**: InVideo AI（通用文字→视频，非专用排名工具）、CapCut 模板（有倒计时模板但无 AI 自动生成排名内容）
**为什么排第二**: "Top 10"是短视频平台最稳定的爆款格式之一。每个排名项揭晓 = 一个 hook，天然高完播率。目前没有任何专用"AI 排名揭晓视频生成工具"

#### 🥉 场景 3：VS 对比动画

**用户场景**: "iPhone 17 Pro vs Samsung Galaxy S27 Ultra — 让数据说话"
**AI 做什么**: 收集两个产品/概念的关键参数 → 生成分屏对比动画（左右各一个，数据依次弹出）→ 自动生成"赢家"总结
**用户编辑什么**: 对比维度、数据值、配色（双方不同的主题色）、最终结论
**导出格式**: 1080x1920 竖屏（或 1:1 方形用于 Instagram），30fps，30-60 秒
**技术路线**: GSAP 分屏动画 + Remotion + LLM 数据收集
**竞品**: **完全空白**。目前没有任何专用 "AI VS 对比视频生成器"。创作者手动用 CapCut 做分屏 + 手动查数据 + 手动打字幕
**为什么排第三**: 竞品完全空白 + VS 内容在任何平台都天然引发讨论（评论区站队） → 高互动率

#### 场景 4：知识卡片/金句动画

**用户场景**: "把《纳瓦尔宝典》的 7 条核心智慧做成 30 秒金句卡片视频发小红书"
**AI 做什么**: 提取书籍/文章的核心金句 → 每句生成一张设计感卡片（含背景图、排版动画）→ 卡片依次过渡
**用户编辑什么**: 金句文字、背景风格（极简/复古/科技感）、字体、过渡动画类型、背景音乐
**导出格式**: 1080x1920 或 1080x1440（小红书 3:4），25-30fps，30-60 秒
**技术路线**: Fabric.js/HTML Canvas 渲染卡片 → GSAP 动画过渡 → Remotion 导出
**竞品**: Canva（手动制作，无 AI 金句提取/自动动画）、QuoteVideo（部分功能但无 AI）
**关键验证**: 微信公众号搜索显示"小红书一套知识卡片能卖多少钱?我的AI制卡副业三个月总结"——说明知识卡片是有变现价值的独立品类

#### 场景 6：AI 新闻简报动画（新增）

**用户场景**: "今天 AI 领域的 5 件大事，30 秒看完"
**AI 做什么**: 与 Visword 信息流引擎共享热点发现 → 每个热点生成一张卡片 → 卡片带标题/摘要/数据 → 自动生成转场动画 → 合成新闻简报视频
**用户编辑什么**: 选择哪些新闻入简报、顺序、每条的时长、片头标题、配音（AI 旁白）
**导出格式**: 1080x1920，30fps，30-90 秒
**独特价值**: 这是 Visword **静态信息流卡片的自然视频化延伸**——同一个热点发现引擎，输出从图片升级为视频

#### 场景 9：年度回顾/Wrapped 动画（新增）

**用户场景**: "我的 2026 GitHub 年度总结——431 次 commit、12 个新项目、最常用的语言是 Rust"
**AI 做什么**: 用户输入数据（或连接 API）→ 生成 Spotify Wrapped 风格的动画页面 → 数据计数动画、彩色过渡、关键词高亮
**用户编辑什么**: 数据、配色、页面顺序、分享文案
**导出格式**: 1080x1920，30fps，30-60 秒
**传播力**: ⭐⭐⭐⭐⭐ — "Wrapped"风格是最强病毒传播格式之一（每年 12 月 Spotify Wrapped 全球刷屏）

## 第四部分：与信息流卡片的协同效应

Visword 的静态信息流（v2 已设计）和动态视频（本报告讨论）共享**同一个热点发现引擎**。这使得产品可以自然演进：

- 用户在信息流中浏览热点卡片 → 看到一个感兴趣的话题 → 点击"生成视频" → 选择场景模板（图表/排名/对比/知识卡） → AI 自动填充内容 → 用户编辑 → 导出 MP4
- 反之，用户从视频场景开始 → 生成动态视频后 → 自动生成配套的静态信息流卡片（用于小红书图文/公众号/LinkedIn 图文）

"卡片 + 视频"双输出是从内容格式上覆盖全平台的策略——静态图征服小红书图文/公众号/ Linkedin，动态视频征服 TikTok/抖音/Reels/Shorts/视频号。

## 第五部分：推荐执行路线图

### Phase 1（第 1-6 周）：首发场景 + 通用导出
- 实现**动态增长曲线/图表动画**场景（bar race + line growth + pie explode）
- 实现**通用导出格式**（MP4 H.264 1080x1920）+ 3 个平台预设（TikTok/抖音/视频号）
- 实现基础编辑器（文字编辑、配色、时长调整）
- 与信息流引擎打通（从热点话题→数据→图表动画）

### Phase 2（第 7-10 周）：排名揭晓 + 对比动画
- 实现 **Top-N 排名揭晓动画**场景
- 实现 **VS 对比动画**场景
- 扩展导出预设至全部 8 个主流平台

### Phase 3（第 11-14 周）：知识卡片 + 新闻简报
- 实现**知识卡片/金句动画**场景
- 实现**AI 新闻简报动画**场景（信息流→视频的直接转化）
- 添加背景音乐库和 AI 旁白（TTS）

### Phase 4（后续）：Wrapped + 更多场景
- 年度回顾/Wrapped 风格、步骤流程、时间线等
- 模板市场（用户可分享和销售场景模板）

## 结论

两个关键转向：(1) **放弃 API 发布**，改为"一键导出 MP4 为各平台最优格式"——技术上更简单（不需要维护 8 个平台的 API 集成），用户体验更好（用户保持对发布过程的控制），法律风险更低（不触及平台的第三方发布限制）；(2) **场景从 5 个扩充至 15 个**，按市场验证度、技术难度、竞品空白三维评分重新排定优先级——动态增长曲线/图表动画保持首发位置，新增排名揭晓和 VS 对比紧随其后，知识卡片/金句动画作为社交传播力最强的轻量场景。

Visword 的产品蓝图从"信息流阅读工具"最终演进为"AI 策展+可视化生成+编辑+跨平台格式导出的创作者工具"——静态卡片和动态视频共享同一个热点发现引擎，覆盖从图文到短视频的全部社交内容格式。
